# Agentic QA runtime

This is the local QA runtime that the platform installs into a target repository as `.agentic-qa/`. It runs multi-agent QA sessions against the target application, checks each session against a deterministic workflow contract, and shows the results in a local dashboard.

The runtime contains no personas, scenarios, or domain rules of its own. They come from discovery, which writes them to `adapter/`. Until discovery has run, the API returns empty persona and scenario lists.

## Layout

```text
.agentic-qa/
├── AGENTIC.md                 # rules for the QA agents (loaded as the global prompt layer)
├── adapter/                   # generated by discover-local for this repository
│   ├── config/                # discovery report, code graph, install metadata
│   ├── personas/  scenarios/  capabilities/  routes/  auth/
│   ├── workflow-contracts/    # one deterministic contract per scenario
│   ├── assertions/  manifest/
│   └── runtime/               # runtime plan and generated hooks
├── packages/
│   ├── api/                   # Fastify API, agent runtime, SQLite session store
│   └── web/                   # React dashboard (Vite)
├── scripts/
│   └── start-local-dashboard.generated.sh
├── data/                      # runtime settings (selected provider and model)
├── .env.example               # copy to .env.local to set provider keys
└── .env.local                 # provider keys; never commit
```

Files whose names contain `.generated.` are rewritten by every discovery run. The platform documentation describes each file and which ones to review (`docs/generated-files.md` in the platform repository).

## Start

```bash
./scripts/start-local-dashboard.generated.sh                       # API 3201, dashboard 5176
./scripts/start-local-dashboard.generated.sh --api-port 3208 --web-port 5184
```

On first start, the launcher installs dependencies and, for frontend repositories, Playwright Chromium. It loads `.env.local` and starts the API on `127.0.0.1` and the dashboard. Open the dashboard, choose the provider in **Settings**, and start a scenario from **Agentic Runs**.

Serve the application under test separately and point the runtime at it with `PLAYWRIGHT_BASE_URL`.

## How a run works

1. `POST /api/p2/runs` starts a session for a scenario. A scenario whose quality gate is `restricted` is rejected.
2. The orchestrator executes the steps in workflow-contract order. Each step goes to the agent for its role, which uses the step's tools (Playwright for frontend capabilities).
3. Sensors check each step. When the session ends, the contract is evaluated: `contract_compliant`, `contract_drift`, or `contract_violated`.
4. Steps, tool calls, screenshots, findings, and verdicts are stored in `persona-qa.db` (SQLite) and shown in the dashboard.

Frontend repositories use Playwright and a model provider (Anthropic or OpenAI). Backend API, CLI, library, monorepo, and unknown repositories run deterministically without a browser or model: the runtime inspects the repository, runs safe probes when a URL or command is configured, and records dry-run artifacts when a real mapping is missing.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` | Key for the provider selected in Settings. Usually set in `.env.local`. |
| `PLAYWRIGHT_BASE_URL` | Base URL of the frontend under test. |
| `HEADLESS` | Set to `false` to watch the browser. |
| `AGENTIC_QA_FORCE_DETERMINISTIC_RUNTIME` | `1` runs frontend scenarios without a model: each step calls its declared tool. Use it for repeatable runs and to tell app failures from agent failures. |
| `GENERIC_API_BASE_URL`, `TARGET_API_BASE_URL`, `API_BASE_URL` | Base URL for backend API probes. |
| `GENERIC_CLI_COMMAND`, `TARGET_CLI_COMMAND` | CLI command to probe when the package `bin` is not enough. |
| `PERSONA_QA_SCENARIOS_FILE`, `PERSONA_QA_PERSONAS_FILE` | Use a hand-edited scenarios or personas file instead of the generated one. |
| `DATABASE_URL` | Path of the SQLite session store (default `persona-qa.db` in the API working directory). |

## Development

The launcher is the supported way to run an installed copy. To work on the runtime itself, edit the template in the platform repository (`templates/persona-qa-dashboard/`), not an installed copy, and run its tests there:

```bash
cd packages/api && npx vitest run            # API and agent runtime tests
cd packages/web && npx vitest run            # dashboard tests
```

To run the parts separately: `npm run dev:api` (API on port 3001 by default) and `npm run dev:web` (Vite on port 5173; set `VITE_API_URL` if the API runs elsewhere).
